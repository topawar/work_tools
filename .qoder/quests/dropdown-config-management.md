# 下拉框配置管理功能设计

## 一、需求概述

### 1.1 背景与目标
当前系统中存在多处硬编码的下拉框选项（如合同状态、中标状态、物项重要性等），这些选项分散在表单定义和模板文件中，维护困难且容易出错。需要将这些下拉框选项统一管理，存储到数据库中，并提供专门的配置管理页面。

### 1.2 核心价值
- 实现下拉框选项的集中化管理，降低维护成本
- 支持动态配置，无需修改代码即可调整选项
- 提升系统的可扩展性和灵活性
- 减少代码冗余，提高代码质量

### 1.3 业务范围
本功能将纳入系统配置模块，与现有的SQL合并策略配置并列，通过侧边栏统一访问。

## 二、功能设计

### 2.1 配置项识别

根据现有代码分析，需要管理的下拉框配置项包括：

| 配置项类型 | 当前代码位置 | 使用场景 | 选项数量 |
|----------|------------|---------|---------|
| 合同状态 | forms.py APPR_STATE_CHOICES | 合同状态修改 | 17个选项 |
| 中标状态 | forms.py BID_STATUS_CHOICES | 合同终止、简化寻源终止 | 2个选项 |
| 是否报送 | forms.py REPORT_CHOICES | 国资委报送 | 2个选项 |
| 物项重要性 | forms.py IMPORTANCE_CHOICES | 物项重要性修改 | 5个选项 |

### 2.2 数据模型设计

#### 2.2.1 配置分组表

用于对下拉框配置进行分类管理。

| 字段名称 | 数据类型 | 约束 | 说明 |
|---------|---------|------|-----|
| id | 自增整型 | 主键 | 分组唯一标识 |
| group_code | 字符串(50) | 唯一、非空 | 分组编码（如：contract_status） |
| group_name | 字符串(100) | 非空 | 分组显示名称（如：合同状态） |
| description | 文本 | 可空 | 分组描述说明 |
| is_active | 布尔 | 非空、默认True | 是否启用 |
| created_at | 日期时间 | 自动填充 | 创建时间 |
| updated_at | 日期时间 | 自动更新 | 更新时间 |

#### 2.2.2 配置项表

存储具体的下拉框选项。

| 字段名称 | 数据类型 | 约束 | 说明 |
|---------|---------|------|-----|
| id | 自增整型 | 主键 | 配置项唯一标识 |
| group | 外键 | 关联分组表 | 所属配置分组 |
| option_code | 字符串(50) | 非空 | 选项值编码（如：ACTIVE） |
| option_label | 字符串(200) | 非空 | 选项显示标签（如：生效） |
| sort_order | 整型 | 非空、默认0 | 排序顺序 |
| is_active | 布尔 | 非空、默认True | 是否启用 |
| is_system | 布尔 | 非空、默认False | 是否系统内置（内置项不可删除） |
| remark | 文本 | 可空 | 备注说明 |
| created_at | 日期时间 | 自动填充 | 创建时间 |
| updated_at | 日期时间 | 自动更新 | 更新时间 |

**约束规则**：
- group 与 option_code 组合唯一
- 确保同一分组下的选项编码不重复

### 2.3 配置管理页面设计

#### 2.3.1 页面布局

页面采用左右分栏结构：

- 左侧：配置分组列表
  - 显示所有配置分组的名称
  - 支持点击切换当前编辑的分组
  - 高亮显示当前选中的分组
  
- 右侧：配置项管理区域
  - 显示当前分组下的所有配置项
  - 支持添加、编辑、删除、排序操作
  - 表格形式展示：选项编码、选项标签、排序、状态、操作按钮

#### 2.3.2 功能交互

**配置分组管理**：
- 查看所有配置分组
- 添加新分组（输入：分组编码、分组名称、描述）
- 编辑分组信息（仅允许修改名称和描述，编码不可修改）
- 启用/禁用分组（禁用后该分组下的所有选项将不可用）

**配置项管理**：
- 查看当前分组下的所有配置项，按排序顺序展示
- 添加新配置项（输入：选项编码、选项标签、排序顺序、备注）
- 编辑配置项（仅允许修改标签、排序、备注）
- 删除配置项（系统内置项显示但禁止删除）
- 启用/禁用配置项
- 拖拽调整排序（可选功能，也可通过输入排序值实现）

**操作验证**：
- 分组编码必须唯一且符合命名规范（仅允许字母、数字、下划线）
- 选项编码在同一分组内必须唯一
- 删除操作需要二次确认
- 系统内置项不允许删除或修改编码

### 2.4 系统集成设计

#### 2.4.1 导航集成

在侧边栏的"系统配置"分组中添加新的菜单项：

**修改导航配置**（navigation.py）：
- 在系统配置分组下添加菜单项：下拉框配置管理
- URL命名：dropdown_config
- 显示标签：下拉框配置管理

**更新后的系统配置分组**：
- SQL合并策略
- 下拉框配置管理（新增）

#### 2.4.2 表单集成

各业务表单需要从数据库动态加载下拉框选项，替代硬编码的CHOICES常量。

**集成方式设计**：

方案一：工具函数方式
- 提供统一的配置加载函数，根据分组编码返回选项列表
- 格式转换为Django表单可用的元组列表格式
- 支持缓存机制提升性能

方案二：自定义表单字段
- 封装动态配置字段类，继承自ChoiceField
- 在字段初始化时自动加载对应分组的选项
- 统一处理缓存和格式转换

**推荐采用方案一**，理由：
- 灵活性高，适用于表单和模板两种场景
- 实现简单，与现有代码改动最小
- 便于后续扩展（如添加过滤条件、支持多语言等）

#### 2.4.3 模板集成

部分模板中硬编码了下拉框选项（如appr_state_change.html），需要改为动态渲染。

**集成策略**：
- 视图层加载配置数据并传递给模板
- 模板使用循环语句动态生成option标签
- 保持现有的CSS类名和JavaScript逻辑不变

**示例流程**：
- 视图函数调用配置加载工具函数获取选项列表
- 将选项列表添加到模板上下文
- 模板使用for循环遍历选项生成HTML

## 三、技术方案

### 3.1 路由设计

新增路由路径如下：

| URL路径 | 视图函数命名 | 功能说明 |
|--------|------------|---------|
| /dropdown-config/ | dropdown_config_view | 配置管理主页面 |
| /dropdown-config/group/add/ | dropdown_group_add | 添加配置分组 |
| /dropdown-config/group/edit/ | dropdown_group_edit | 编辑配置分组 |
| /dropdown-config/group/toggle/ | dropdown_group_toggle | 启用/禁用分组 |
| /dropdown-config/item/add/ | dropdown_item_add | 添加配置项 |
| /dropdown-config/item/edit/ | dropdown_item_edit | 编辑配置项 |
| /dropdown-config/item/delete/ | dropdown_item_delete | 删除配置项 |
| /dropdown-config/item/toggle/ | dropdown_item_toggle | 启用/禁用配置项 |
| /dropdown-config/item/reorder/ | dropdown_item_reorder | 调整排序 |

### 3.2 视图层设计

#### 3.2.1 主视图函数

**功能职责**：
- 处理GET请求：加载所有配置分组和当前选中分组的配置项
- 默认选中第一个分组
- 支持通过查询参数指定选中的分组
- 准备模板所需的上下文数据

**输入参数**：
- 可选查询参数：group_id（指定当前选中的分组）

**输出内容**：
- 渲染配置管理页面模板
- 传递分组列表、当前分组、配置项列表到模板

#### 3.2.2 配置操作视图

采用POST请求处理各项配置操作，操作完成后重定向回主页面。

**通用处理流程**：
- 验证请求方法为POST
- 验证请求参数的合法性
- 执行数据库操作（新增、修改、删除）
- 记录操作日志
- 返回操作结果（成功时重定向，失败时返回错误信息）

**错误处理**：
- 参数校验失败：返回400错误或在页面显示错误消息
- 数据库操作失败：捕获异常并记录日志，返回友好的错误提示
- 权限验证：预留扩展点，未来可集成权限控制

### 3.3 配置加载工具设计

#### 3.3.1 工具函数接口

**函数签名**：
- 函数名：get_dropdown_options
- 输入参数：
  - group_code（字符串）：配置分组编码
  - include_empty（布尔，默认True）：是否包含空选项
  - empty_label（字符串，默认"请选择"）：空选项的显示文本
- 返回值：元组列表，格式为 [(选项编码, 选项标签), ...]

**函数行为**：
- 根据分组编码从数据库查询启用的配置项
- 按排序顺序排列
- 根据参数决定是否在列表开头插入空选项
- 返回Django表单兼容的格式

#### 3.3.2 缓存策略

为提升性能，配置数据应采用缓存机制：

**缓存方案**：
- 使用Django内置的缓存框架
- 缓存键格式：dropdown_options_{分组编码}
- 缓存时长：默认30分钟（可配置）
- 缓存失效触发：配置项发生增删改操作时主动清除对应缓存

**缓存更新策略**：
- 配置保存后立即清除相关缓存
- 支持手动全量刷新缓存的管理接口
- 缓存未命中时自动从数据库加载并存入缓存

### 3.4 模板设计

#### 3.4.1 页面模板结构

模板文件命名：dropdown_config.html

**页面布局**：
- 继承现有的基础布局（包含侧边栏）
- 使用Bootstrap响应式布局
- 左右分栏采用Flexbox或Grid布局

**核心元素**：
- 顶部标题和操作按钮区域
- 左侧分组列表（可滚动）
- 右侧配置项表格（支持内联编辑）
- 弹窗表单（用于添加/编辑操作）

#### 3.4.2 交互逻辑

**前端行为**：
- 点击分组时通过AJAX加载对应的配置项（或使用页面跳转）
- 添加/编辑操作使用模态框弹窗
- 删除操作显示确认对话框
- 操作成功后显示提示消息（类似现有的保存成功通知）

**表单验证**：
- 前端实时验证输入格式（如编码格式、必填项）
- 后端二次验证确保数据完整性
- 显示清晰的错误提示信息

#### 3.4.3 样式设计

**设计原则**：
- 保持与现有系统配置页面一致的风格
- 使用Bootstrap组件确保响应式布局
- 表格采用简洁的样式，重点突出可操作性

**关键样式元素**：
- 分组列表项：悬停效果、选中状态高亮
- 配置项表格：斑马条纹、悬停高亮行
- 操作按钮：图标+文字，颜色区分不同操作类型
- 状态标识：启用（绿色）、禁用（灰色）、系统内置（标签）

## 四、数据迁移方案

### 4.1 迁移步骤

**阶段一：数据库准备**
- 创建配置分组表和配置项表的数据库迁移脚本
- 执行迁移创建表结构

**阶段二：初始数据导入**
- 编写数据迁移脚本，将硬编码的CHOICES常量转换为数据库记录
- 标记初始数据为系统内置项
- 执行数据导入

**阶段三：代码切换**
- 修改表单定义，使用配置加载工具替代硬编码常量
- 修改模板文件，动态渲染下拉框选项
- 保留原有常量作为备份（标记为已废弃）

**阶段四：测试验证**
- 验证各表单的下拉框选项显示正确
- 测试配置管理页面的增删改查功能
- 确认数据同步和缓存机制正常

**阶段五：清理**
- 确认系统稳定后，移除已废弃的硬编码常量
- 清理无用的代码注释和临时代码

### 4.2 兼容性处理

**向后兼容策略**：
- 在过渡期内，配置加载工具在数据库无数据时回退到硬编码常量
- 提供配置完整性检查工具，确保所有必需的配置项已迁移
- 记录警告日志，提醒管理员完成配置迁移

**回滚方案**：
- 保留原有硬编码常量，便于紧急回滚
- 提供配置导出功能，备份数据库中的配置数据
- 迁移脚本支持可逆操作

## 五、扩展性考虑

### 5.1 未来扩展方向

**多语言支持**：
- 为配置项表增加语言字段
- 根据用户语言偏好返回对应的选项标签

**权限控制**：
- 集成用户权限系统，限制配置管理操作的访问权限
- 区分查看权限和编辑权限

**配置版本管理**：
- 记录配置项的变更历史
- 支持配置回滚到历史版本

**级联配置**：
- 支持父子级联的下拉框配置（如省市区联动）
- 扩展数据模型增加父级关联字段

**配置导入导出**：
- 提供Excel导入导出功能，便于批量配置
- 支持配置在不同环境间的迁移

### 5.2 性能优化预留

**数据库索引**：
- 为group_code、option_code、sort_order建立索引
- 为is_active字段建立索引优化查询

**查询优化**：
- 使用select_related减少关联查询
- 对高频访问的配置采用更长的缓存时间

**前端优化**：
- 配置项列表采用分页或虚拟滚动（当数据量大时）
- 使用前端缓存减少重复请求

**性能问题应对**：
- 对配置加载工具进行性能测试
- 优化数据库查询和索引设计
- 监控缓存命中率并调整策略

**兼容性问题应对**：
