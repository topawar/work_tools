# 项目打包问题排查与解决方案设计

## 一、问题背景

项目当前无法正常打包，需要支持以下需求：

1. 支持两种打包方式：目录模式和单文件模式
2. 数据库文件不在运行时生成，直接复制已有数据库文件到打包产物中
3. 临时文件使用相对路径，写入到打包文件夹中
4. 支持启动时指定端口

## 二、问题排查分析

### 2.1 现有配置存在的问题

#### 问题一：数据库文件缺失

- **现象**：spec 文件配置中引用了 `db.sqlite3` 和 `db_template.sqlite3`，但项目根目录下实际不存在这些文件
- **影响**：打包时无法找到数据库文件，导致打包失败
- **根本原因**：数据库文件在项目初始化时通过 Django 迁移动态生成，未预先创建用于打包的数据库文件

#### 问题二：临时文件路径配置使用硬编码绝对路径

- **现象**：
  - 配置文件 `app_config.json` 中 `SQL_OUTPUT_BASE_PATH` 使用绝对路径 `D:\临时文件`
  - 代码中 `base.py` 硬编码 `SQL_BASE_DIR = r"D:\临时文件"`
- **影响**：打包后程序在其他环境运行时无法写入临时文件，可能因路径不存在或权限问题导致功能失败
- **根本原因**：未使用运行时基础目录的相对路径机制

#### 问题三：静态文件路径配置不完整

- **现象**：spec 文件中引用 `work_tools/static`，但未确认该目录是否存在及内容
- **影响**：如果静态文件目录不存在，打包可能失败或打包后界面资源缺失

#### 问题四：三个 spec 文件配置不统一

- **现象**：
  - `work_tools.spec`：配置较旧，引用 `db_template.sqlite3`，缺少 collect_all 依赖收集
  - `work_tools_onedir.spec`：配置较新，引用 `db.sqlite3`，使用 collect_all
  - `work_tools_onefile.spec`：配置较新，引用 `db.sqlite3`，使用 collect_all
- **影响**：配置不一致容易导致打包结果不稳定，维护困难

#### 问题五：缺少打包自动化脚本

- **现象**：当前需要手动执行 pyinstaller 命令
- **影响**：打包流程繁琐，容易出错，效率低下

### 2.2 运行时路径机制分析

项目已在多处实现运行时基础目录检测机制：

- `settings.py` 中的 `get_runtime_base()` 函数
- `config.py` 中的 `_get_runtime_base_dir()` 函数
- `base.py` 中的 `get_runtime_base_dir()` 函数

判断逻辑：检测 `sys.frozen` 属性

- 打包后运行：返回可执行文件所在目录
- 源码运行：返回项目 BASE_DIR

但该机制未在临时文件路径配置中得到有效应用。

## 三、解决方案设计

### 3.1 数据库文件预生成策略

#### 3.1.1 数据库文件准备流程

1. 在项目根目录下预先创建用于打包的 SQLite 数据库文件 `db.sqlite3`
2. 通过 Django 迁移命令初始化数据库结构
3. 执行初始化数据填充（如下拉框配置数据）
4. 将该数据库文件作为打包资源随产物一同发布

#### 3.1.2 数据库文件复制策略

打包配置中将数据库文件复制到打包产物：

- 目录模式：复制到 `dist/work_tools/` 目录
- 单文件模式：打包到可执行文件内部资源，运行时解压到临时目录

#### 3.1.3 运行时数据库路径解析

保持现有 `settings.py` 中的数据库路径配置：

```
BASE_DIR / "db.sqlite3"
```

确保运行时基础目录机制正确指向打包后的数据库文件位置。

### 3.2 临时文件相对路径改造

#### 3.2.1 默认临时文件目录策略

修改临时文件默认基础路径从硬编码绝对路径改为相对于运行时基础目录：

- 默认临时文件目录：`{RUNTIME_BASE_DIR}/temp_files`
- SQL 输出目录：`{RUNTIME_BASE_DIR}/temp_files/sql_output`
- 日志目录（已实现）：`{RUNTIME_BASE_DIR}/logs`

#### 3.2.2 配置文件路径策略

配置文件 `app_config.json` 的默认值调整：

- `SQL_OUTPUT_BASE_PATH`：从 `D:\临时文件` 改为相对路径标识，如 `./temp_files/sql_output`
- 运行时通过 `config.py` 解析为绝对路径

#### 3.2.3 临时文件目录初始化

在应用启动时自动创建必要的临时文件目录：

- `temp_files/sql_output`：SQL 文件输出目录
- `temp_files/downloads`：临时下载文件目录
- `logs`：日志文件目录（已存在）

#### 3.2.4 代码改造范围

需修改的模块：

- `work_tools/config.py`：调整默认配置，添加相对路径解析逻辑
- `work_tools/views/base.py`：移除硬编码的 `SQL_BASE_DIR`，统一使用配置读取

### 3.3 端口参数支持（已实现）

分析发现 `run_app.py` 已实现端口参数支持：

- 通过 `--port` 或 `-p` 参数指定端口
- 默认端口：8000
- 无需额外改造

### 3.4 打包配置优化

#### 3.4.1 spec 文件统一与优化

##### 目录模式 spec 文件（work_tools_onedir.spec）

优化要点：

- 数据资源路径：修正数据库文件路径为实际存在的 `db.sqlite3`
- 配置文件包含：确保包含 `config/app_config.json`
- 临时目录创建：无需在 spec 中处理，由运行时代码创建
- 依赖收集：保持使用 `collect_all` 收集 Django 和 openpyxl 完整依赖
- 隐藏导入：保持现有所有视图模块的隐藏导入配置

数据文件包含清单：
| 源路径 | 目标路径 | 说明 |
|--------|----------|------|
| db.sqlite3 | . | 数据库文件 |
| config/ | config/ | 配置文件目录 |
| work_tools/templates/ | work_tools/templates/ | 模板文件 |
| work_tools/static/ | work_tools/static/ | 静态资源（如存在） |
| work_tools/migrations/ | work_tools/migrations/ | 迁移文件 |

##### 单文件模式 spec 文件（work_tools_onefile.spec）

与目录模式保持一致的数据文件配置，差异仅在于 EXE 配置：

- 所有依赖打包到单个可执行文件
- 运行时临时目录自动解压资源

#### 3.4.2 废弃旧配置文件

删除或归档 `work_tools.spec` 旧版配置文件，避免配置混乱。

### 3.5 打包自动化脚本设计

#### 3.5.1 打包脚本功能需求

创建批处理脚本 `build.bat`，提供以下功能：

1. 环境检查：验证 PyInstaller 是否已安装
2. 数据库准备：确认数据库文件存在，如不存在则执行迁移生成
3. 清理旧产物：删除 `dist/` 和 `build/` 目录
4. 执行打包：支持选择打包模式（目录/单文件）
5. 验证打包结果：检查输出产物是否生成成功
6. 提示启动测试：提示用户如何启动测试打包产物

#### 3.5.2 脚本交互设计

脚本运行流程：

1. 显示打包模式选择菜单
   - 选项 1：目录模式打包
   - 选项 2：单文件模式打包
   - 选项 3：同时打包两种模式
2. 执行对应的打包命令
3. 输出打包进度和结果
4. 提供测试运行建议

#### 3.5.3 数据库初始化集成

脚本在打包前自动检查并初始化数据库：

- 检查 `db.sqlite3` 是否存在
- 如不存在，执行 Django 迁移命令创建
- 执行初始化数据填充脚本（如存在）

### 3.6 配置文件路径适配

#### 3.6.1 配置文件加载路径

`config.py` 中的 `_path()` 函数已实现运行时路径适配：

- 源码运行：`{BASE_DIR}/config/app_config.json`
- 打包运行：`{EXE_DIR}/config/app_config.json`

确保该机制在打包后能正确加载配置文件。

#### 3.6.2 配置文件随打包发布

spec 配置中已包含配置文件目录：

```
('config', 'config')
```

保持现有配置，确保打包后配置文件存在。

## 五、配置文件调整方案

### 5.1 app_config.json 默认值调整

调整前：

```
{
  "SQL_OUTPUT_BASE_PATH": "D:\\临时文件",
  ...
}
```

调整后：

```
{
  "SQL_OUTPUT_BASE_PATH": "./temp_files/sql_output",
  ...

```

### 5.2 路径解析策略

在 `config.py` 中添加路径解析函数：

- 如果路径为相对路径（以 `./` 开头），则基于运行时基础目录解析为绝对路径
- 如果路径为绝对路径，则直接使用（兼容用户自定义配置）

### 5.3 配置迁移策略

对于已有用户配置文件：

- 保持向后兼容，仍可使用绝对路径
- 新安装的程序使用相对路径默认值
- 提供配置界面允许用户修改路径配置

## 六、风险评估与应对

### 6.1 潜在风险

| 风险项                             | 风险等级 | 影响范围     | 应对措施                                                     |
| ---------------------------------- | -------- | ------------ | ------------------------------------------------------------ |
| 数据库文件体积过大导致打包产物膨胀 | 低       | 打包体积     | 数据库只包含结构和必要的基础数据，避免预置业务数据           |
| 相对路径解析在不同环境下行为不一致 | 中       | 跨平台兼容性 | 充分测试 Windows 不同环境，使用 os.path 标准库确保路径兼容性 |
| 单文件模式下资源解压性能问题       | 低       | 启动速度     | PyInstaller 自动处理，首次解压后缓存，影响可控               |
| 临时文件目录权限问题               | 中       | 临时文件写入 | 代码中添加目录创建时的异常处理，失败时回退到用户临时目录     |
| 打包后程序体积过大                 | 低       | 分发便利性   | 通过 excludes 排除不必要的依赖，优化打包配置                 |

### 6.2 回滚预案

如打包改造后出现问题，可执行以下回滚操作：

1. 恢复 `work_tools.spec.backup` 为 `work_tools.spec`
2. 恢复 `config.py` 和 `base.py` 代码修改
3. 恢复 `app_config.json` 配置文件
4. 使用旧版配置重新打包

## 七、打包脚本使用说明

### 7.1 脚本执行方式

在项目根目录下执行：

```
build.bat
```

### 7.2 打包产物位置

- 目录模式：`dist/work_tools/work_tools.exe` 及其依赖文件
- 单文件模式：`dist/work_tools.exe`

### 7.3 启动打包产物

目录模式：

```
dist\work_tools\work_tools.exe
```

单文件模式：

```
dist\work_tools.exe
```

指定端口启动：

```
work_tools.exe --port 8080
```

不自动打开浏览器：

```
work_tools.exe --no-browser
```

### 7.4 打包后目录结构

#### 目录模式结构

```
dist/work_tools/
├── work_tools.exe          # 主程序
├── _internal/              # 依赖库和资源
│   ├── ...                 # PyInstaller打包的依赖
├── db.sqlite3              # 数据库文件
├── config/                 # 配置文件目录
│   └── app_config.json
├── temp_files/             # 临时文件目录（运行时创建）
│   └── sql_output/
└── logs/                   # 日志目录（运行时创建）
```

#### 单文件模式结构

```
dist/
├── work_tools.exe          # 单文件可执行程序
运行后在exe所在目录自动创建：
├── db.sqlite3              # 数据库文件（首次解压）
├── config/                 # 配置文件目录（首次解压）
├── temp_files/             # 临时文件目录（运行时创建）
└── logs/                   # 日志目录（运行时创建）
```
