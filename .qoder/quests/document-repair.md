# 单据生成语句中 ops_remark 字段缺失修复方案

## 1. 问题背景与目标

在系统中，许多单据生成的 SQL 语句需要包含`ops_remark`字段用于记录操作备注。但在代码审查过程中发现，部分模块在生成 SQL 语句时遗漏了该字段，这将导致无法追踪相关操作记录。

本方案旨在全面检查并修复所有单据生成语句中缺失`ops_remark`字段的问题，确保所有相关操作都能正确记录操作备注信息。

## 2. 影响范围分析

根据代码库分析，以下模块存在生成 SQL 语句时遗漏`ops_remark`字段的情况：

### 2.1 已确认包含 ops_remark 的模块

- 重要性维护 (importance.py)
- 政府报告设置 (gov_report.py)
- 项目轮次修改 (project_round.py)
- 合同明细修改 (contract_item.py)
- 合同价格修改 (contract_price.py)
- 计划日期修改 (plan_date.py)
- 合同终止 (contract_terminate.py)
- 寻源终止 (sourcing_terminate.py)
- ERP 终止 (erp_terminate.py)
- 订单执行人修改 (order_executor.py)
- 合同单位修改 (contract_unit.py)
- 可配置数据修改 (configurable_data.py)
- 适用清单修改 (use_list.py)
- 审批状态修改 (appr_state.py)

### 2.2 待检查与修复的模块

需要进一步检查以下模块是否存在 ops_remark 字段缺失问题：

- 其他可能生成 UPDATE 语句的模块

## 3. 修复策略

### 3.1 修复原则

1. 确保所有 UPDATE 语句都包含`OPS_REMARK`字段
2. 在回退语句中正确处理`OPS_REMARK`字段的还原
3. 保持现有功能逻辑不变，仅补充缺失字段
4. 遵循各模块现有的代码风格和结构

### 3.2 修复方法

1. 对于逐条生成 SQL 的模块，在构建 SET 子句时添加`OPS_REMARK`字段
2. 对于合并生成 SQL 的模块，在合并逻辑中确保包含`OPS_REMARK`字段
3. 在回退语句生成部分，同样需要处理`OPS_REMARK`字段的还原
4. 确保字段值经过适当转义处理，防止 SQL 注入

## 4. 实施步骤

### 4.1 第一阶段：全面扫描

1. 使用代码扫描工具识别所有生成 UPDATE 语句的位置
2. 分析每个位置是否正确包含了`OPS_REMARK`字段
3. 建立缺失清单，包括文件路径、函数名、具体位置

### 4.2 第二阶段：分类修复

1. 对于简单缺失的模块，直接添加`OPS_REMARK`字段处理逻辑
2. 对于复杂逻辑的模块，确保在各种分支条件下都正确处理该字段
3. 特别注意回退语句的处理，确保能正确还原该字段

### 4.3 第三阶段：验证测试

1. 编写单元测试验证修复后的 SQL 生成逻辑
2. 进行集成测试确保不影响现有功能
3. 检查生成的 SQL 语句格式是否正确

## 5. 风险评估与控制

### 5.1 主要风险

1. 遗漏某些边缘场景导致修复不完整
2. 修改现有逻辑引入新的 bug
3. 回退语句处理不当导致数据异常

### 5.2 控制措施

1. 建立完整的检查清单，确保覆盖所有模块
2. 充分的单元测试和集成测试
3. 代码审查机制，多人确认修复效果
4. 提供回滚方案，以防修复引入严重问题

## 6. 验收标准

1. 所有生成 UPDATE 语句的模块均正确包含`OPS_REMARK`字段
2. 相关的回退语句也正确处理了`OPS_REMARK`字段
3. 不影响现有功能的正常运行
4. 通过所有相关的单元测试和集成测试 3. 不影响现有功能的正常运行
