# 表单合并优化设计方案

## 1. 需求背景与目标

### 1.1 当前问题分析

目前项目中的表单处理存在以下局限：

1. 只能处理单一类型的业务操作，无法满足组合式业务需求
2. 用户需要同时修改多个字段（如单价和物资编码）时，必须分别在不同表单中操作
3. 生成的 SQL 文件需要手动合并，增加了操作复杂度和出错风险
4. 缺乏统一的文件合并机制，导致用户体验不佳

### 1.2 优化目标

1. 实现多表单数据的一站式处理能力
2. 提供自动化 SQL 文件合并功能
3. 保持现有表单功能的完整性和兼容性
4. 提升用户操作效率，降低人工干预需求

## 2. 设计方案概述

### 2.1 核心思路

引入表单合并处理机制，允许用户在一个操作流程中处理多种业务需求，并自动生成合并后的 SQL 文件。

### 2.2 技术实现路径

1. 增强前端界面，支持多表单选择和数据输入
2. 扩展后端处理逻辑，实现跨表单数据整合
3. 利用现有 SQL 合并策略，生成优化的合并 SQL
4. 提供统一的文件输出接口

## 3. 项目备份策略

### 3.1 备份重要性

在实施表单合并功能前，必须对当前项目进行完整备份，以确保在出现意外情况时能够快速恢复到原始状态。

### 3.2 备份方案

1. **Git 版本控制备份**

   - 创建新的分支用于功能开发：`feature/form-merge`
   - 提交当前主分支的完整状态作为基准点
   - 添加提交信息："备份：表单合并功能开发前的完整状态"

2. **文件系统备份**

   - 复制整个项目目录到安全位置
   - 确保包含所有配置文件、数据库文件和代码文件
   - 记录备份时间和版本信息

3. **数据库配置备份**
   - 导出当前的`db.sqlite3`数据库文件
   - 备份`app_config.json`配置文件
   - 保存所有 MERGE_MODULES 配置状态

## 4. 功能详细设计

### 4.1 前端界面设计

#### 4.1.1 多表单选择面板

- 提供复选框形式的表单选择区域
- 显示各表单的简要说明和功能范围
- 支持全选/取消全选功能

#### 4.1.2 动态表单区域

- 根据用户选择的表单动态加载对应的输入字段
- 保持各表单原有的字段校验规则
- 提供清晰的表单分隔标识

#### 4.1.3 统一操作按钮

- 生成合并 SQL 按钮
- 清除所有输入按钮
- 表单切换快捷操作

### 4.2 后端处理逻辑

#### 4.2.1 数据收集与验证

- 接收来自多个表单的数据
- 对各表单数据分别进行原有校验逻辑处理
- 汇总验证结果，统一返回错误信息

#### 4.2.2 SQL 生成策略

- 为每个表单调用其原有的 SQL 生成方法
- 将生成的 SQL 语句按照执行顺序进行分类整理
- 在适当位置添加分隔注释，提高可读性

#### 4.2.3 文件合并机制

- 将多个 SQL 文件的内容合并为一个完整的 SQL 文件
- 添加整体文件头注释，说明包含的业务内容
- 保持原有各部分的结构和注释信息

### 4.3 配置管理扩展

#### 4.3.1 新增配置项

在现有的 SQL 合并策略配置基础上，增加表单合并相关配置：

- 表单合并功能开关
- 合并文件命名规则
- 输出格式选项

## 5. 系统架构设计

### 5.1 组件交互关系

```
graph TD
    A[用户界面] --> B[表单合并控制器]
    B --> C[表单数据验证模块]
    B --> D[SQL生成协调器]
    D --> E[各表单SQL生成器]
    D --> F[SQL合并引擎]
    F --> G[文件输出管理器]
    G --> H[存储系统]
```

### 5.2 数据流向

1. 用户在界面选择需要合并的表单并填写数据
2. 控制器接收所有表单数据并进行初步验证
3. 协调器依次调用各表单的 SQL 生成方法
4. 合并引擎整合所有 SQL 内容并优化格式
5. 文件输出管理器保存合并后的文件

## 6. 关键技术实现要点

### 6.1 表单兼容性处理

- 保留各表单原有的独立处理能力
- 通过适配器模式对接不同的表单处理逻辑
- 确保新增合成功能不影响现有功能

### 6.2 SQL 合并策略应用

- 复用现有的 SQL 合并算法和配置
- 在合并过程中维持各部分的独立性
- 保证合并后 SQL 的正确性和可执行性

### 6.3 错误处理机制

- 分别捕获各表单处理过程中的异常
- 提供详细的错误定位信息
- 支持部分成功场景下的结果输出

## 7. 性能与安全考虑

### 7.1 性能优化

- 并行处理多个表单的 SQL 生成任务
- 合理控制内存使用，避免大文件处理时的性能问题
- 提供进度反馈，改善用户体验

### 7.2 安全保障

- 继承原有表单的安全校验机制
- 防止 SQL 注入等安全风险
- 文件路径安全检查，防止越权访问

## 8. 部署与维护

### 8.1 部署要求

- 无需额外依赖，基于现有系统组件实现
- 配置项向后兼容，不影响现有部署

### 8.2 维护策略

- 日志记录详细的操作过程，便于问题追踪
- 提供配置开关，可在必要时快速关闭功能
- 文档更新，确保团队成员了解新功能使用方法
